# 7.11 50 m terrain grid for the 2D map and forecast fields

Status: proposed
Owner:
Source: Follow-up to 7.6 (measured there) and the optional item 4 of 4.27. Not in scope.md.

## Description
The per-cell power and comms fields (7.6) read 0.5-0.8° too clear on ridges and peaks, because the 100 m `GET /terrain` grid misses small rises close to the rover that the backend's 20 m data sees. Measured in 7.6 at the centre cell against `/analyze`:

| Site | Comms agreement, 100 m | Comms agreement, 50 m |
|---|---|---|
| Peak near Shackleton | 95.4% | 99.2% |
| Connecting Ridge | 85.2% | 92.3% |

Serve the grid at 50 m cells (481×481):
- Send heights as compact int16 binary or base64, not a JSON number list, so the download stays small.
- Keep the shadow pass fast enough to scrub. At 50 m it is about 50 ms per pass, against about 13 ms at 100 m. Options are a Web Worker (7.7 already adds one for the forecast) or 50 m for the fields only.

## Expected user interaction
The 2D map looks sharper when zoomed in. The forecast heatmap agrees more closely with the site's own time series on ridges and peaks.

## Done when
- Centre-cell comms agreement with `/analyze` is at least 99% at Peak near Shackleton and 92% at Connecting Ridge
- Scrubbing stays smooth
- `/terrain` response stays well under 5 MB
- Backend tests and `npm run build` pass
