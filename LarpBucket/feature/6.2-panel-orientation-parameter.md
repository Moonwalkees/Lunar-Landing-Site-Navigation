# 6.2 Panel orientation parameter

Status: open
Owner:
Source: scope.md > Core 4 Metrics (Power: vertical Sun-tracking panel), Model (Power)
Priority: medium
Depends on: 3.1

## Description
The `cos(sun_el)` term is only correct for a vertical panel that tracks the Sun in azimuth. Add a `panel` parameter to `power()`: `vertical` (default, `cos(sun_el)`) and `horizontal` (`sin(sun_el)`), clamped at 0 for negative elevation. Expose it on `POST /analyze` as an optional field. Keep `vertical` the default so scope.md is unchanged.

## Why it is useful
Vertical panels suit the poles, where the Sun stays within a few degrees of the horizon. Away from the poles (Apollo sites, CLPS targets in the scope presets) a horizontal or tilted array is the realistic choice.

## Impact of not having it
At low-latitude presets the vertical panel gives ~0 W at local noon, the sunniest time, so power, Wh/day and battery survival look wrong or absurd. Compare would rank non-polar sites unfairly against polar ones.

## Expected user interaction
User picks a preset like Apollo 11 and sees sensible daytime power. A panel-type option (default vertical) is available in the API.

## Done when
- `horizontal` gives 0 at sun_el = 0 and 1361 * area * efficiency at 90°
- `vertical` results are unchanged from 3.1
- Unit tests for both modes
