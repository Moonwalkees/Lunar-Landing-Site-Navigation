# 7.7 Forecast frames: cache and Web Worker

Status: open
Owner:
Source: Extension feature (user request: near-future power/comms change heatmap)
Depends on: 7.6

## Description
Compute, off the main thread, how each cell's power or comms value changes over the next `k` time steps:

- **Δ:** `V(i+k) − V(i)`
- **Worst dip:** `min(V[i..i+k]) − V(i)`, which is always ≤ 0. It catches short blackouts that recover before `i+k`.

To build:
- `frontend/src/forecast.worker.ts`: holds the terrain grid and an LRU cache of per-step frames (about 32 `Float32Array`s, keyed `body:step`). Moving from `i` to `i+1` during playback computes only the one new frame, `i+1+k`.
- `frontend/src/forecast.ts`: a hook `useForecast(grid, analysis, i, k, body, mode)`. It posts requests to the worker, drops stale replies and keeps the last field until a new one arrives, so scrubbing never blocks.
- At the end of the window, `i+k` is clamped to the last step, and the hook reports the real span in hours.

## Expected user interaction
None directly. With the overlay on (7.9), the heatmap follows the scrubber and playback without stutter.

## Done when
- Scrubbing at Shackleton stays smooth with the overlay on
- A cold jump to a new index fills in within about 150 ms
- Worst-dip values are always ≤ 0
- `npm run build` passes
