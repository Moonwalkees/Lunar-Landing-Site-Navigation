# 5.3 Host the frontend

Status: done
Owner: Maddie
Source: tech-stack.md > Stack (Hosting)
Depends on: 5.2
Note: Frontend live on Dokploy (nginx image) at space.universal-approximation.com, built with VITE_API_URL as a build arg.

## Description
Deploy `frontend/` to Vercel with `VITE_API_URL` pointing at the hosted backend.

## Expected user interaction
Judges open one link and can run a preset, a custom site, drag the scrubber and compare sites.

## Done when
- Verification checklist in tech-stack.md passes on the hosted URL

## Solution
**Chosen:** Hosted on Dokploy (not Vercel) from the new `frontend/Dockerfile` (Build Path `/frontend`): `npm ci && npm run build`, then nginx serves `dist/` on container port 80, at `https://space.universal-approximation.com`. `VITE_API_URL` is passed as a **build arg** (`https://space-backend.universal-approximation.com`, including the scheme, no trailing slash). `frontend/package-lock.json` was regenerated so `npm ci` works.

**Strengths**
- Static site on nginx, no runtime config; the same image works on any host.
- Both apps are on one Dokploy server with Let's Encrypt HTTPS.

**Limitations**
- `VITE_API_URL` is baked in at build time, so changing it needs a rebuild. Without `https://` the browser treats it as a relative path and requests go to the frontend's own address (404 from nginx).
- No SPA fallback in nginx; fine while the app has one page.
- The tech-stack.md verification checklist (preset, custom site, scrubber, compare) was not run end to end on the hosted URL after the final `VITE_API_URL` fix.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Vercel (as in tech-stack.md) | The backend already lives on Dokploy. | Free CDN and automatic builds, but a second platform to manage. |
| Nixpacks / Railpack, no Dockerfile | No `start` script in `package.json`; less predictable than a plain nginx image. | One fewer file, but less control over how `dist/` is served. |
| Route `/api` through the frontend's nginx | Needs a proxy config and both apps on one network. | One domain and no CORS, but more setup. |
