# 1.3 Fetch and crop LOLA DEMs

Status: done
Owner: Aiken
Source: tech-stack.md > Stack (Terrain), Build order 1

## Description
Extend `fetch_data.py` with a `dems` command: download `LDEM_85S_20M` (polar, 20 m) and `LDEM_64` (global, ~473 m) from the PDS Geosciences node, with their labels. Crop the polar DEM to the area around the preset south pole sites to keep the size down. Save as GeoTIFF in `backend/data/dem/`.

## Expected user interaction
Developer runs `python scripts/fetch_data.py dems`; cropped GeoTIFFs appear and open with `rasterio`.

## Done when
- Both DEMs open in `rasterio` with correct CRS (polar stereographic / equirectangular)
- Height at a known point (e.g. Shackleton rim) is plausible
- Total size is small enough to bake into a Docker image (aim < 400 MB)

Note: done. `fetch_data.py dems` writes `ldem_85s_20m_crop.tif` (cropped 45 km around the preset polar sites, with overviews) and `ldem_64.tif` to `data/dem/`, 373 MB together, as 16-bit half-metre heights with the scale recorded in the file.

## Solution
**Chosen:** `backend/scripts/fetch_data.py dems` downloads `LDEM_85S_20M` and `LDEM_64` from the PDS Geosciences node, keeps the polar map only within 45 km of the preset south pole sites, and writes both to `backend/data/dem/` as 16-bit GeoTIFFs in half metres (the scale is stored in the file). `--keep-raw` keeps the downloads.

**Strengths**
- 373 MB on disk instead of several GB, and `rasterio` can read small windows from it.
- Half-metre steps are finer than the LOLA height error, so nothing useful is lost by using 16 bits.
- One command, same script as the kernels, so setup stays two lines.

**Limitations**
- A polar site more than 45 km from every preset falls back to the global map (about 473 m per pixel), which is too coarse for a polar skyline. Widen the crop or add the site to `sites.py` and re-run.
- The first run still downloads the full polar file before cropping.
- The data is not in git. Each machine has to run the command once.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Keep the whole 20 m polar map | Several GB per machine | Any polar site at full detail, but slow to set up |
| Store heights as 32-bit floats | Twice the size for no gain | No scale factor to remember when reading |
| LOLA 5 m site tiles | Only cover a few named sites | Sharper ridge crests, 16 times the data per area |
