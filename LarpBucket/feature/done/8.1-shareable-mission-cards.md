# 8.1 Shareable mission cards

Status: done
Owner: Aiken
Source: X-factors (team brainstorm, not yet in scope.md)
Note: done. MISSION CARD in the site console and each row's ⋮ menu makes a PNG card in the board's style with a QR code; the link restores the site, window, rover and time.

## Description
Capture a location/mission as a shareable "card". Possible forms: trading card, boarding pass or poster. Shows lat/lon plus sun and Earth visibility as stats, and the location as an image (possibly stylised with AI). Includes a URL or QR code so others can load the same state.

## Expected user interaction
User clicks share and gets a card image with the site's stats and a URL/QR that opens the app in the same state.

## Done when
- Card shows lat/lon, sun and Earth visibility and a location image
- URL/QR on the card restores the state

## Solution
**Chosen:** A poster-style card drawn on a canvas (`frontend/src/board/drawCard.ts`), 1200 px wide, following doc/style.md: the site name, latitude and longitude, the time and its status word, score, % sunlit, % Earth contact, % Sun + Earth, longest dark, the terrain from above (the hero map's `GET /terrain` grid as round dots, dithered to three tones with the 4x4 Bayer matrix, shadows from `terrain2d.sunlight()` for the card's time, Sun and Earth directions as solid discs), a Sun / Earth / both / battery dot strip over the window with an empty battery marked, survival (the backend's `survives`: SURVIVES or BATTERY RUNS OUT, with the longest dark against the hours a full battery lasts at the rover's load) beside the rover and its numbers, and a QR code. Trimmed at the user's request to one verdict or number per block; the eclipse, the Sun and Earth angles and the explanatory lines were dropped. `board/MissionCard.tsx` shows it full screen with DOWNLOAD PNG, COPY LINK and CLOSE; it opens from MISSION CARD in the console or a row's ⋮ menu and keeps the time it was opened at. The link (`board/share.ts`) always points at the hosted app (`VITE_PUBLIC_URL`, default `https://space.universal-approximation.com/`), so a card made while developing still opens for anyone. It is plain query parameters: `site`, `lat`, `lon`, `start`, `days`, `step`, `solar`, `batt`, `use`, `t`. `BoardApp` reads them once at load, checks each part with the forms' rules, selects the preset at the same place or adds a custom site, then clears them from the address bar so a reload doesn't re-apply them. The QR code comes from `qrcode-generator` (MIT, no dependencies), drawn as dark modules on a `--regolith` square with whole-pixel modules.

**Strengths**
- The picture is the real terrain and shadows, from data the page already has, with no server work or image service.
- The link needs nothing stored: anyone with the app open at that address gets the same site, window, rover and time.
- Checked in the browser: the QR code decodes to the link, and the link restores a preset, a custom site, a 30-day window and a custom rover.

**Limitations**
- Board UI only; the classic UI has no card.
- The link opens the hosted app, which must be on a version with this feature; a card made from a branch that isn't deployed opens the deployed version.
- The card is one time step; it does not animate.
- Custom sites other than the shared one are not in the link.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| AI-stylised location image | Needs an image service and a key; the real dithered terrain already fits the board | Could look more like a poster |
| Screenshot the page or the Unity view (`html-to-image`, `preserveDrawingBuffer`) | Another dependency, and the 3D view is only loaded for some sites | Shows exactly what the user sees |
| Short links stored on the backend | Needs storage and an endpoint the night before submission | Shorter URL, smaller QR code |
| Trading card or boarding pass layout | A poster leaves room for the terrain and the window strip | A smaller, more playful card |
