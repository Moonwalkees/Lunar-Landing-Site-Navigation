# 4.4 Horizon panorama chart

Owner: Maddie

Style: doc/style.md > Colour, Type, Open decisions 2-3 (palette, Doto labels; Plotly vs dot-matrix charts is undecided)
Depends on: 4.2
Note: Plotly panorama with filled skyline, Sun/Earth tracks (solid above the skyline, dotted behind it) and scrubber-linked markers; lazy-loaded.

## Description
Add `react-plotly.js` and replace the placeholder in `Panorama.tsx`: filled terrain skyline (az 0-360 vs el), Sun and Earth tracks over the window, and markers for their positions at the scrubber time.

## Expected user interaction
After Analyze, the user sees the skyline with Sun and Earth paths; dragging the scrubber moves the two markers.

## Done when
- Markers follow the scrubber
- Hover shows az/el

## Solution
**Chosen:** `frontend/src/components/Panorama.tsx` draws the analysis from `POST /analyze` with `react-plotly.js` (via `react-plotly.js/factory`). It shows the filled skyline, the Sun and Earth tracks over the window, and one marker each at the scrubber time. Each track is split into a solid part (Sun `fraction > 0`, Earth `margin >= 0`) and a dotted part where terrain hides it. A marker is filled when the body is visible now and hollow when it is hidden. Hover shows az, el and the UTC time. Tracks break where azimuth wraps 360°→0°. The y-range fits the skyline and both whole tracks, but stops 10° below the horizon so the Sun's night side doesn't flatten low-latitude skylines. `App.tsx` passes `tracks` (null when the site has changed since the last Analyze, so a stale skyline is never shown) and lazy-loads the panel with `React.lazy`. Checked in headless Chrome on Shackleton, Connecting Ridge and Apollo 11: the markers move with the scrubber, and hover works.

**Strengths**
- Follows the agreed stack (`react-plotly.js`); zoom, pan and hover come built in. `uirevision` keeps the user's zoom while the markers move.
- Static traces are memoized on the analysis, so scrubbing only replaces the two markers.
- Solid and dotted tracks show at a glance when terrain blocks the Sun or Earth, which is what the panorama is for.
- Lazy loading keeps Plotly (~1.4 MB gzipped) out of the main bundle (~76 kB gzipped), so the form and cards don't wait for it.

**Limitations**
- `plotly.js` is installed as an npm alias of `plotly.js-dist-min` (`package.json`). The default `react-plotly.js` entry imports `plotly.js/dist/plotly`, which the minified package doesn't ship, hence the factory.
- Plotly mutates the layout it is given, so `Panorama` passes a fresh copy every render. Reusing the memoized object dropped `height` and collapsed the chart after the first scrub.
- Still the placeholder palette (the same Sun/Earth hex as `TimeSeries.tsx`) and system font. Applying doc/style.md tokens and Doto is 4.8's job, and style.md open decision 2 (Plotly vs dot-matrix canvas) is still unanswered.
- Only one 29.5-day window is drawn, so the Sun track doesn't quite close (a small gap where the window starts and ends).
- Fill closes against the bottom of the initial range; zooming out further below it shows unfilled space.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Custom canvas like `TimeSeries.tsx` | The ticket and tech-stack.md name `react-plotly.js`; style.md decision 2 is still open | Small bundle and dot-matrix look, but hover, zoom and axes by hand |
| `plotly.js-dist-min` with a hand-written `Plotly.react` wrapper | Drops `react-plotly.js`, which the stack names | One dependency fewer, no alias |
| Full `plotly.js` package | Large source build, slow Vite startup | None worth it for one chart |
| Fit the y-range to the visible parts of the tracks only | On a crater floor (Shackleton) both tracks vanished off the chart | Tighter skyline zoom on rim sites |
