# 8.3 Background reacts to Sun and Earth visibility

Status: done
Owner: Maddie
Source: X-factors (team brainstorm, not yet in scope.md); accepted by the user 2026-11-15
Note: done. `html.los` shows a faint stepped-static layer behind the page while the selected site has no Earth line of sight (`board.css`, `BoardApp.tsx`, style.md). Brightness half was 4.17.

## Description
Make the background depend on visibility at the scrubber time.
- Slightly lighter when the Sun is in view, darker when it is not. (Already built in 4.17.)
- No static when Earth is in view, a small amount of static when it is not.

## Expected user interaction
As the scrubber moves, the background lightens/darkens with the Sun and gains/loses static with Earth.

## Done when
- Background brightness follows Sun visibility
- Static overlay follows Earth visibility

## Solution
**Chosen:** `frontend/src/board/BoardApp.tsx` toggles `html.los` when the selected row's state is `sunonly` or `dark` (Earth blocked), mirroring the `html.lit` effect from 4.17. `frontend/src/board/board.css` adds a `body::before` layer: fixed, `z-index: -1`, `pointer-events: none`, tiled with an inline SVG `feTurbulence` noise tinted `--regolith`. It fades to `opacity: .2` over 1.2 s (raised from `.14`, briefly `.28`, then eased back to `.2` at the user's request after user feedback that it was invisible; the noise alpha ramp was also steepened to `4 -2` for harder grain) and jumps between five offsets with a `steps(1)` animation every 0.5 s. `body` lost its own background so the layer can sit between the `html` background and in-flow content. Under `prefers-reduced-motion` the static still shows but holds still. `doc/style.md > Rendering rules` records it as the one allowed use of noise.

**Strengths**
- Pure CSS with no canvas or per-frame JS. It reuses the same selected-row state as the lit background, so it follows the scrubber and site changes automatically.
- Hard-step jitter matches style.md's "status changes in hard steps" rule and avoids the smooth shimmer that rule warns about.

**Limitations**
- It only shows in gaps between panels. Opaque surfaces (the 3D map's black canvas, captions, the dock, the 88% console) cover it.
- `marginal` Earth still counts as comms (same as `isAos`), so a marginal site shows no static.
- Tuned in headless Chrome screenshots: `.14` was invisible, `.42` buried dim text (ghost rows, captions), `.28` read clearly; the user then asked for it a little subtler, so it is now `.2`.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Full-screen overlay above content | The user asked for static in the background, and it would grain the text | Would be visible over the 3D map too |
| Animated canvas noise | Per-frame JS cost and smooth shimmer, which style.md rejects | Truer TV-static look |
