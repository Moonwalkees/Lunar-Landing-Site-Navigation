# 4.22 Switch between board and classic UI at runtime

Status: done
Owner: Maddie
Note: done. A CLASSIC VIEW / BOARD VIEW button (`src/UiSwitch.tsx`) flips UIs at runtime; choice in `src/uiChoice.ts` (`?ui=` > saved > `VITE_UI` > board); README, tech-stack.md and style.md updated.
Source: doc/tech-stack.md > Frontend (two UIs); user request 2026-11-15

## Description
Add a button at the top-right of both UIs (CLASSIC VIEW on the board, to the right of the clock stats in the console button style; BOARD VIEW on classic) so a user can flip between them without rebuilding. `VITE_UI` stays as the default; the user's choice is remembered and can also be forced with `?ui=board` / `?ui=classic`.

## Expected user interaction
On the board, the user clicks CLASSIC VIEW at the top-right; the page reloads into the classic UI, which has the same switch at its top-right to go back. The choice sticks on reload.

## Done when
- Button at the top-right of both UIs
- Choice order: `?ui=` > remembered choice > `VITE_UI` > board
- Works when browser storage is unavailable (falls back to the default)
- README, tech-stack.md, style.md updated
- `npm run build` passes

## Solution
**Chosen:** `src/uiChoice.ts` has `currentUi()` (`?ui=` first, then `localStorage["lunar-ui"]`, then `VITE_UI`, then board) and `switchUi()` (saves the choice and navigates with `?ui=`). `src/main.tsx` calls `currentUi()` instead of reading `VITE_UI` directly. `src/UiSwitch.tsx` is one button naming the other UI. On the board it sits after `.clock` in a new `.hud-right` row, styled like the console's `.cbtn`. In classic it floats right in the header. Verified on a production build (`vite preview`): board to CLASSIC VIEW to classic, reload stays classic, BOARD VIEW to board.

**Strengths**
- No rebuild needed, and `VITE_UI` still works as the default, so existing deploy configs are unchanged.
- Storage access is wrapped in try/catch. When it is blocked, the `?ui=` link still carries the choice.

**Limitations**
- Switching reloads the page, because each UI's global CSS would otherwise leak into the other. In-memory state (custom sites, scrub time) is lost.
- Both UI chunks now ship in every build. Only the chosen one loads, but the classic UI's Plotly chunk is in `dist/`.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Swap UIs in place without reload | Both stylesheets set global `body`/`html` rules and would clash | Keeps state across the switch |
| BOARD \| CLASSIC segmented switch | First version; the user asked for a single board-style button instead | Shows both options at once |
