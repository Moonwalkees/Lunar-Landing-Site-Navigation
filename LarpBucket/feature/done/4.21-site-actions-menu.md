# 4.21 Site actions menu (kebab) on board rows and the console

Status: done
Owner: Maddie
Note: done. New `SiteMenu.tsx` (⋮ with GO TO SITE / SURFACE VIEW / DELETE) on every board row and the console; CUSTOM tag removed; presets can be deleted (hidden for the session).
Source: doc/style.md > Board, Site console; user request 2026-11-15

## Description
Add a kebab (⋮) menu at the right end of each board row, and the same menu on the map console for the selected site. Options: go to the site (select it and scroll to the map), open the surface view for it, and delete it from the board. Drop the "CUSTOM" tag on custom rows.

## Expected user interaction
User clicks ⋮ on a row and picks GO TO SITE, SURFACE VIEW or DELETE. DELETE removes the site from the board, ranking and pins. The console shows the same ⋮ menu for the selected site.

## Done when
- ⋮ menu on every row and on the console, with the three actions
- Delete works for presets and custom sites; the last remaining site can't be deleted
- No CUSTOM tag
- Menu works with keyboard (Escape closes) and doesn't trigger the row's own click
- `npm run build` passes

## Solution
**Chosen:** `frontend/src/board/SiteMenu.tsx` is a ⋮ button with a popover menu. It closes on outside pointerdown or Escape, and swallows clicks and keys so the row underneath isn't selected. `BoardApp.tsx` builds the actions per site with `actions(id)`:
- `onGo` calls `select(id, true)` (select and scroll to the map).
- `onSurface` selects the site and calls `setOpen3D(true)`.
- `onDelete` calls `removeSite`. It drops a custom site, or adds a preset to a `hidden` set filtered out of `sites`, and moves the selection if the deleted site was selected. It is `null` (shown disabled) when only one site is left.

`Board.tsx` adds the menu as a 10th grid column (a 4th `mn` area on phones) and drops the CUSTOM tag. The console shows the same three actions as a stacked list of `.cbtn` buttons in `.console-btns` (from `actions(sel.id)`; DELETE in `--selected`), replacing its single SURFACE VIEW button. This was changed from a ⋮ menu at the user's request. Verified in headless Chrome: 5 row menus and 1 console menu, opening the menu doesn't change the selection, Escape closes it, GO TO selects and scrolls, DELETE removes the row, and the console's SURFACE VIEW opens the detail view.

Follow-up (user request): the console also shows the selected site's coordinates under its name (`.console .coord`, `LAT -89.67° · LON 129.78°E`, 2 decimals, east-positive like the add-site form).

Follow-up (user request): the console's status word (e.g. DARK·LOS) moved from under the name to two separate `.kv` readouts right of MAX DARK, LIT and COMMS (YES/NO, like the board's columns; first tried as one stacked NOW cell). The five readouts then got equal-width columns (`repeat(5, minmax(0, 1fr))`, 12 px gap), so the console widened from 340 to 520 px to fit a `100.0` value, and on phones LIT and COMMS wrap to a second row, and the old `.st` styles were removed.

**Strengths**
- One component and one action builder, so rows and the console always offer the same options.
- The old "Remove" chips under the Add custom site form were dropped at the user's request (the ⋮ DELETE replaces them). `AddSite` now takes only `onAdd`.

**Limitations**
- Deleted presets come back on reload. Nothing is persisted, matching custom sites, which are also session-only.
- No arrow-key navigation between menu items. Tab works.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Inline icon buttons per row instead of a menu | Three extra columns crowd the 400 px layout | One tap fewer |
| Delete custom sites only | The user asked for delete on every row | Presets would always stay on the board |
