## Description
Build the approved dot-matrix departure-board design as a second frontend in `frontend/src/board/`, fed by the real backend (`GET /sites`, `POST /analyze`, `GET /terrain`). Keep the current site unchanged as the "classic" UI. `VITE_UI` picks which one is built: unset or `board` gives the new design, `classic` gives the old site.

Agreed with the user on 2026-11-15 (answers style.md open decision 1):
- The hero is a three.js 3D map of the real terrain around the selected site, rendered with the dot-matrix dither. `three` is added to the stack.
- The existing unfiltered Unity orbit and surface views (`TerrainView3D`) open when the user drills into a site.

The board needs the Core items too: site picker and custom lat/lon, date window and step, the horizon panorama, all metrics, power / battery / comms over time, and side-by-side comparison through the ranked board.

## Expected user interaction
User opens the app and sees a full-bleed dot-matrix terrain map of the default south pole site with the Sun's real shadows, the lamp strip, a ranked board of every preset site with real metrics, a dot chart and skyline for the selected site, and the time dock at the bottom. Tapping a board row or pin selects that site, and the map loads its terrain. **SURFACE VIEW** on the console opens the unfiltered detail view: Unity surface (default) and orbit, plus the 2D bird's-eye map with its pan / zoom / height readout. Scrubbing moves the Sun, the shadows, the lamps, the NOW column and every chart together. Setting `VITE_UI=classic` and rebuilding brings back the old site.

## Done when
- `VITE_UI=classic` builds the old site unchanged; unset or `board` builds the new one
- Every number on the board comes from the backend; nothing is sample data
- Tokens, type, square chrome and dither follow `doc/style.md`
- Layout works at 400 px with no horizontal scroll
- `npm run build` passes in both modes

## Solution
**Chosen:** A second frontend in `frontend/src/board/`, picked in `frontend/src/main.tsx` by `VITE_UI` (unset or `board` gives the board; `classic` loads `src/classic.tsx`, which mounts the untouched `App.tsx` and `styles.css`). Each UI is its own dynamic chunk with its own CSS, so a build only ships one of them: the board build has no Plotly and the classic build has no three.js.
- `BoardApp.tsx` calls `POST /analyze` for every preset and custom site over one shared window (default: today, 29.5 days, 1 h steps). One time index drives every panel.
- `HeroMap.tsx` uses three.js with the `GET /terrain` heights at true scale, including the Moon's curvature. Per-cell sunlight comes from `terrain2d.sunlight()` and is uploaded as a texture. The shader applies a 4x4 Bayer dither to `--space` / `--ash` / `--regolith`, and the map renders at 2-3 px cells under a round-dot CSS mask.
- `Detail3D.tsx` wraps the existing `TerrainView3D` (Unity, unfiltered). It also offers `TerrainMap` (the 2D bird's-eye map) as a **2D MAP** tab, opens on SURFACE, and opens from **SURFACE VIEW** or by tapping the selected pin. Esc closes it. The mock's FLY TO SITE button was removed at the user's request.
- `Board.tsx` (ranked rows, sort chips, best value per column underlined), `DotChart.tsx` (sun / Earth / both plus power and battery), `Skyline.tsx` (the panorama as dots), and `Panels.tsx` (lamps, all metrics, mission window and add-site form, time dock).
- `data.ts` holds the score, status words and 6 h cells.

**Strengths**
- Follows `doc/style.md` and the approved mock (tokens, Doto ≥ 18 px, square chrome, ordered dither, hard-step lamps, touch sizes), with every number coming from the backend.
- Map shadows use the same code as the 2D bird's-eye view, so the two views agree.
- The classic UI is unchanged, so teammates' in-progress work there (e.g. 4.5 `TimeSeries.tsx`) is not affected.
- Lat/lon are text inputs parsed on submit, so a minus sign can be typed (avoids BUG-005 in the new UI).

**Limitations**
- The map covers only the 24 km around the selected site, so other sites' pins appear only if they lie inside it. With today's presets that is just the selected pin.
- The score weights (0.4 / 0.3 / 0.3) come from the mock, not from scope.md.
- The board analyses every site on load (5 requests). Fine for 5 presets, but slow if many custom sites are added.
- Map frame rate on a phone is not yet measured (style.md open decision 6). It was checked in headless Chrome with SwiftShader only.
- The board chunk is about 200 kB gzipped, mostly three.js.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Restyle the existing UI in place (ticket 4.8) | The user wanted the old site kept and switchable | One codebase, but no way back to the old look |
| 2D dot-matrix map, no three.js | The user approved adding three.js to match the mock | No new dependency, but no orbit or zoom |
| Dither the Unity view as the hero | The 68 MB download on page load; the user wanted Unity unfiltered | One 3D engine, but a heavy first load |
| Runtime switch (URL query) instead of a build-time env var | The user asked for an env var; a build-time switch keeps each bundle to one UI | Could flip without rebuilding, but both UIs would ship |
