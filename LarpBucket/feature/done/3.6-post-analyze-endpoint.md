# 3.6 POST /analyze

Status: done
Owner: Aiken
Source: scope.md > Core 2-5, tech-stack.md > Stack (API)
Note: done. `analyze()` in `app/analysis.py` and `POST /analyze` in `app/main.py`; kernels load in the lifespan, the ephemeris radians are converted to degrees once, bad input gives 422 and missing data 503.

## Description
`POST /analyze` takes `{lat, lon, startDate, days, stepHours}` and returns skyline (az, el), time array, Sun/Earth tracks, power, battery, comms state and the metrics object. Field names must match `frontend/src/types.ts` (`Metrics`). No caching.

Ephemeris notes (from 1.2): call `ephemeris.load_kernels()` in the FastAPI lifespan so no request loads kernels. `sun_earth_azel` takes UTC strings and returns numpy arrays in **radians** (`np.degrees(...).tolist()` if the frontend expects degrees); it raises `ValueError` for a bad lat/lon and SPICE errors for unparseable times, so map those to 422. SPICE calls are serialized by `ephemeris.SPICE_LOCK`.

## Expected user interaction
Frontend sends a site and window; gets everything needed for all panels in one response.

## Done when
- Response validated by pydantic models
- One-month, 1 h step request returns in a few seconds

## Solution
**Chosen:** `analyze()` in `backend/app/analysis.py` joins the other modules: `ephemeris.sun_earth_azel` (radians, converted to degrees once), `horizon.skyline`, the power, battery and comms functions in `utils.py` (the comms ones are from ticket 3.3) and `eclipse`. `POST /analyze` in `backend/app/main.py` validates the request with pydantic and returns degrees throughout. Kernels load in the FastAPI lifespan. A bad site or window gives 422, missing kernels or maps give 503, and a window over `MAX_STEPS = 20_000` is refused.

**Strengths**
- One request fills every panel, with field names matching `frontend/src/types.ts`.
- `analysis.py` holds no maths of its own, so each module is still tested alone.
- A year at a 2 h step runs inside the test suite in about a second.

**Limitations**
- Panel area and efficiency are the fixed defaults in `constants.py` (1 m2, 30%), not request fields.
- No caching, as the ticket says; repeated requests recompute.
- The ephemeris places the site on the mean-radius sphere, so site height is not included in the directions. The effect is far below 0.01 degrees.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| One endpoint per panel | More round trips and the panels could disagree | Smaller responses |
| Return radians, as the ephemeris does | Every frontend panel shows degrees | No conversion in the backend |
