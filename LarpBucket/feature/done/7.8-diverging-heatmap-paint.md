# 7.8 Diverging heatmap paint and legend

Status: done
Owner: Tony Pham
Note: done. `paintDelta()` and the overlay colours in `terrain2d.ts`, `ForecastLegend.tsx`, and legend styles in both UIs. The paint was checked on a rendered image; the legend has not been seen in a browser, because nothing mounts it until 7.9.
Source: Extension feature (user request: near-future power/comms change heatmap). Follows doc/style.md for colour.
Depends on: 7.7

## Description
Draw a change field (−1 to +1) over the existing 2D map without hiding the terrain:

- Add `paintDelta(base: ImageData, delta: Float32Array, opacity)` in `frontend/src/terrain2d.ts`.
  - It blends a diverging scale over the relief image: red for losing, transparent for no change, teal/blue for gaining.
  - It uses the same 2× bilinear upsample as `paint()`.
  - Values with |Δ| < 0.02 stay transparent, so noise doesn't tint the map.
- Legend: a gradient bar labelled "losing … gaining", the body (POWER / COMMS), the mode (Δ / WORST DIP) and the span ("next 12 h", or "next 4 h (end of window)").
- Take colours from `board/palette.ts` tokens where possible. The ramp must stay readable for colour-blind viewers.

## Expected user interaction
With the overlay on, the user sees red where power or comms will drop over the next k steps and blue where it will improve. A legend explains the colours and the time span.

## Done when
- Heatmap is readable over both sunlit and shadowed ground
- Zero change is fully transparent
- Legend shows body, mode and span in hours
- `npm run build` passes

## Solution
**Chosen:**
- `frontend/src/terrain2d.ts`:
  - `paintDelta(base, delta, opacity = 0.8)` returns a new image: the base turned grey, with `DELTA_LOSS` (`#f0595e`) blended in where the value falls and `DELTA_GAIN` (`#3388ee`) where it rises. It uses the same 2× bilinear upsample as `paint()`, through a shared `upsampleAxis()` helper.
  - `deltaAlpha(d)` is the overlay strength: 0 up to `DELTA_DEADBAND = 0.02`, a short fade-in, then 35% rising to 100% at |Δ| = 1.
- `frontend/src/components/ForecastLegend.tsx`: `ForecastLegend({ body, mode, hours, cut })`. The gradient bar is built from the same colours and `deltaAlpha`, so it matches the map. In worst-dip mode it shows the losing half only.
- Styles: `.terrain-legend*` in `frontend/src/styles.css` (classic) and `frontend/src/board/board.css` (board), bottom right of the map.

Differences from the description:
- **The base map is greyed under the overlay.** The map's own colours are warm for sunlit and blue for shadow, and blue shadow next to blue "gaining" was ambiguous. With a grey base, colour only ever means change.
- **Colours are not palette tokens.** `--selected` is the nearest red but is reserved for selection, and `--earth` teal is the Earth's colour on the same map. The pair was chosen with the dataviz validator instead.

Checks:
- Colour pair on a mid-grey surface: colour-blind separation ΔE 21.7 (target 8 or more), normal-vision ΔE 32.3, contrast 3:1 or more, lightness and chroma in band.
- In Node, on the Peak near Shackleton grid: zero change gives exactly the greyed base; a change of 0.02 everywhere leaves no tint; full loss and full gain give the exact colours; the base image is not modified. About 15 ms per paint at 482×482.
- Rendered the plain map, power Δ, power worst dip and comms Δ side by side and looked at them: the overlay reads on both sunlit and shadowed ground, and relief stays visible through it.
- `npm run build` passes.

**Strengths**
- Colour has one meaning while the overlay is on, and shadow is still visible as dark grey.
- Small changes are visible (35% floor) and noise is not (dead-band).
- The legend cannot drift from the map, because both use the same constants and curve.

**Limitations**
- The legend has not been rendered in a browser. Its layout and wording should be checked when 7.9 mounts it.
- Strength is opacity over terrain of varying brightness, so magnitude is read approximately. The exact numbers are in the 7.9 hover readout.
- About 15 ms per paint on the main thread, on top of the base paint, each time the forecast or Sun position changes.
- Sign is carried by colour alone on the map. The legend labels both ends, and the pair is colour-blind safe, but there is no texture alternative.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Blend over the coloured map (no greying) | Blue shadow and blue gain were hard to tell apart | Keeps the familiar warm / blue look |
| Teal for gaining, as in the description | Too close to the Earth arrow's `--earth` teal | Closer to the board palette |
| A second canvas layer over the map | Needs its own pan, zoom and resize handling | Could change opacity without repainting |
| Opaque diverging scale with a grey midpoint | Hides the terrain, which the planner needs for routing | Magnitude would read more exactly |
