# 4.14 Lamp strip: fixed SITES / LIT + AOS fills, drop IN SHADOW

Status: done
Owner: Maddie
Source: doc/style.md > Layout (Lamp strip), Annunciator lamps; user request 2026-11-15
Note: done. SITES is always `--regolith`, LIT + AOS is always `--ok`, and the IN SHADOW lamp is removed (`Panels.tsx`, `board.css`, style.md).

## Description
On the board's annunciator lamp strip:
- The SITES lamp is always filled white (`--regolith`).
- The LIT + AOS lamp is always filled green (`--ok`), even when the count is 0.
- The IN SHADOW lamp is removed.

LIT and EARTH AOS keep their old behaviour: filled only when the count is non-zero.

## Expected user interaction
User sees four lamps: a white SITES lamp, LIT (amber when any site is lit), EARTH AOS (blue when any site has Earth), and a green LIT + AOS lamp, including when its count is 0. On phones the four lamps sit in a 2x2 grid.

## Done when
- SITES is always `--regolith`, LIT + AOS always `--ok`
- No IN SHADOW lamp
- 4 columns on desktop, 2x2 below 560 px
- style.md matches
- `npm run build` passes

## Solution
**Chosen:** In `Lamps` (`frontend/src/board/Panels.tsx`), SITES gets a fixed `lit` class and LIT + AOS a fixed `ok` class. The `dark` count and its lamp are removed. `frontend/src/board/board.css` adds `.lamp.lit` (`--regolith` fill, `--space` text), changes the grid to 4 columns, and drops the mobile rule that stretched the first lamp across the top, so phones get a 2x2 grid. `doc/style.md` (Lamp strip and Annunciator lamps) is updated to match.

**Strengths**
- Reuses the existing lamp classes and tokens, with no new colours.

**Limitations**
- A green LIT + AOS lamp at 0 no longer signals state by its fill alone. The count has to carry it.

**Alternatives considered**
Only one sensible approach. This was a direct user request.
