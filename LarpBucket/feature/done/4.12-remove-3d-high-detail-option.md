# 4.12 Remove the High detail option from the 3D view

Status: done
Owner: Aiken
Source: follows 4.9 (3D terrain view), which is not in scope.md yet. Requested by the 3D view's owner.
Note: done. The High detail button, the H key and the two `*_hi.png` files are gone; `frontend/public/unity/` is a new build without the feature.

## Description
The 3D view had a **High detail** button that downloaded a finer version (3.9 m, about 12 MB) of the two tiles made from LOLA 5 m data. Remove it everywhere: the button in the panel, the H key inside the view, the code behind it in the Unity build, and the finer terrain files.

## Expected user interaction
The terrain panel shows Bird's-eye view, Orbit view and Surface view only. Pressing H inside the 3D view does nothing. The terrain is always at its standard detail (a height every 8 m).

## Done when
- No High detail button in the terrain panel
- No `*_hi.png` in `frontend/public/unity/StreamingAssets/`
- Pressing H in the 3D view requests nothing

## Solution
**Chosen:** Removed the button and its state from `frontend/src/components/TerrainView3D.tsx`, and the `highDetail` flag from `frontend/src/terrain.ts`. Deleted `site01_hi.png` and `site04_hi.png`. Rebuilt the Unity view without the `SetDetail` message and the H key, so nothing in the build can ask for the removed files.

**Strengths**
- 23 MB less in `frontend/public/unity/`.
- One less control to explain, and no case where two areas have the option and two do not.

**Limitations**
- Close-up surface views of Connecting Ridge and Shackleton rim are at 8 m, not 3.9 m.
- To bring it back, the Unity view has to be rebuilt with the feature restored; the finer source heightmaps are still in the Unity project.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Hide the button but keep the files and the code | 23 MB of files nothing uses, and the H key would still fetch them | Could be switched back on without a rebuild |
