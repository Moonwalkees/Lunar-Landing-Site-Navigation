# 4.3 Load presets from GET /sites

Status: done
Owner: Maddie
Source: scope.md > Core 1 Observer placement
Style: doc/style.md > Components > Board (the dropdown stays; a board-row preset list is an open decision)
Depends on: 3.5
Note: dropdown now loads from GET /sites with Custom last; opens on the first south pole preset and today; offline falls back to one site + Custom with a note.

## Description
Replace the hardcoded list in `frontend/src/sites.ts` with data from `GET /sites`, keeping "Custom" as an option. Load the default south pole site and today's date on open.

## Expected user interaction
User opens the app; the dropdown lists backend presets and a south pole site is preselected.

## Done when
- Dropdown populated from the API; falls back gracefully if the API is down

## Solution
**Chosen:** `getSites()` in `frontend/src/api/client.ts` fetches `GET /sites` and drops malformed entries. `App.tsx` calls it once on mount (`useEffect`) and keeps the list in `useState`; `SiteForm.tsx` renders it with "Custom" always last. The app opens on `defaultSite()` from `frontend/src/sites.ts` (the first preset with lat ≤ -80°, i.e. a south pole site) and today's UTC date. `sites.ts` no longer holds the preset list, only `FALLBACK_SITE` (a copy of the backend's first south pole preset), the `CUSTOM` label and `defaultSite()`. Added a `Preset` type in `types.ts`.

**Strengths**
- The backend's `app/sites.py` is the only preset list, so fixing a preset (e.g. BUG-003) fixes the dropdown with no frontend change.
- Backend down: the app still opens on a south pole site with a usable Custom option, and the form says presets are unavailable instead of showing an empty dropdown.
- If the user picks or types a site before `/sites` answers, the late response doesn't overwrite it.
- Picking "Custom" now keeps the current lat/lon instead of jumping to 0, 0.

**Limitations**
- `FALLBACK_SITE` duplicates one entry from `backend/app/sites.py` and must be kept in step by hand.
- The default is chosen by rule (first preset south of -80°) rather than flagged by the backend. Today that is Shackleton crater, which BUG-003 says sits on the crater floor.
- No retry: if the backend comes up after the page loads, a reload is needed to get the presets.
- Still a plain `<select>`; board-row presets from doc/style.md are an open decision and 4.8's job.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Keep the full hardcoded list as the offline fallback | Two preset lists to keep in step, which the ticket says to replace | Offline demo would keep every preset |
| Add a `default: true` flag to `GET /sites` | Changes the 3.5 API contract for one bit of UI | Backend would decide the default explicitly |
| Show the presets error in the main header error banner | That banner is for Analyze failures; a presets outage isn't blocking | More visible |
