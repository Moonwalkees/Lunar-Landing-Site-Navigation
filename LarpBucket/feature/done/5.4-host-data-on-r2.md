# 5.4 Host the finished DEMs on Cloudflare R2

Status: done
Owner: Maddie
Source: tech-stack.md > Stack (Hosting)
Depends on: 5.1
Note: fetch_data.py reads an optional DATA_URL (public R2 bucket) so the image build takes about a minute instead of hours.

## Description
Downloading and cropping the raw LOLA maps (~2.4 GB) during the Docker build took hours from the Dokploy server. Upload the finished GeoTIFFs (`ldem_85s_20m_crop.tif`, `ldem_64.tif`, ~370 MB) to a public Cloudflare R2 bucket and let `fetch_data.py dems` download them from `DATA_URL` when it is set.

## Expected user interaction
Deploying the backend on any host builds in a couple of minutes with no manual data copying.

## Done when
- `DATA_URL` set: `fetch_data.py dems` downloads the two `.tif` files from it and skips the raw NASA download
- `DATA_URL` unset: behaviour is unchanged
- Backend Dockerfile takes `DATA_URL` as a build arg and the image serves `/analyze` on Dokploy

## Solution
**Chosen:** `backend/scripts/fetch_data.py` now reads an optional `DATA_URL` env var. When set, `fetch_dems` downloads the finished `ldem_85s_20m_crop.tif` and `ldem_64.tif` from it and skips the raw LOLA download and crop; when unset, behaviour is unchanged. `backend/Dockerfile` takes `DATA_URL` as a build arg and runs the fetch during the build. The two files (~370 MB) are in a public Cloudflare R2 bucket, served from its `pub-….r2.dev` address. `download()` sends a `User-Agent` header because R2 returns 403 to Python's default `Python-urllib`.

**Strengths**
- Build went from hours (about 0.1 MB/s from the NASA archive on the server) to about a minute.
- Optional: builds without `DATA_URL` still work as before, so nobody is forced onto R2.
- R2 has no download fees and the data is public domain, so a public bucket needs no credentials.

**Limitations**
- If the DEMs or the preset sites used to crop the polar map change, the two files must be re-cropped locally and re-uploaded by hand.
- The `r2.dev` address is a Cloudflare development URL with rate limits; a custom domain would be the production option.
- Kernels still come from NAIF at build time.

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Download and crop the raw LOLA maps in the build | About 2.4 GB at 0.1 MB/s from the server; hours per build. | No extra hosting, but unusable build times. |
| Bind-mount the data from the server | Manual copy, tied to one machine. | Quick to set up, not repeatable. |
| GitHub Release assets | The repo is private, so the build would need a token. | Free, but credentials in the build. |
| Bake `backend/data/` into git | `data/` is gitignored and ~415 MB. | No external host, but a very heavy repo. |
