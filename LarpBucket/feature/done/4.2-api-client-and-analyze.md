# 4.2 API client and Analyze button

Status: done
Owner: Aiken
Source: scope.md > Minimum user interaction 2-4
Style: doc/style.md > Status words, Rendering rules (loading and error states use the board vocabulary; ghosted values while loading)
Depends on: 3.6

## Description
Add `frontend/src/api/client.ts` with `analyze(site)` calling `POST /analyze` (base URL from `VITE_API_URL`, default `http://localhost:8000`). Wire the Analyze button in `App.tsx`, with loading and error states.

## Expected user interaction
User clicks Analyze; a loading state shows, then metric cards fill with real values. Errors show a short message.

## Done when
- Metric cards show backend values
- Backend down → visible error, app doesn't crash

Note: done. `src/api/client.ts` plus loading and error states in `App.tsx`; the `Analysis` response type is in `types.ts`. The restyle to status words (doc/style.md) is not done here.

## Solution
**Chosen:** `frontend/src/api/client.ts` has `analyze(site)`, which posts to `VITE_API_URL` (default `http://localhost:8000`) and turns a failed request into a readable message. `App.tsx` keeps `analysis`, `analyzing` and `error` in `useState`; `SiteForm.tsx` disables the button while a request runs. The `Analysis` type is in `types.ts`.

**Strengths**
- Plain `fetch` and `useState`, as the stack says.
- Backend error text (422 detail) is shown to the user as is.

**Limitations**
- A request in flight is not cancelled if the user presses Analyze again.
- Loading and error text are not yet in the board style from doc/style.md (see 4.8).

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| A data-fetching library (React Query, SWR) | The stack lists plain `useState` | Caching and cancel for free |
