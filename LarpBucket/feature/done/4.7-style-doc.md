# 4.7 Frontend style document

Status: done
Owner: Maddie
Source: tech-stack.md > Stack (Frontend); design review of the dot-matrix departure board mocks

## Description
Write `doc/style.md`, the visual design reference for the frontend: colour tokens, Doto type rules, dot sizes, board and map components, mobile and touch rules, and links to the reference mocks.

## Expected user interaction
Developers open `doc/style.md` before touching frontend styles and follow it. No app behaviour changes.

## Done when
- `doc/style.md` exists and links the reference mocks
- Frontend tickets 4.1-4.6 point to it
- Open decisions (3D map scope, Plotly vs dot charts) are listed, not decided

Note: done. Doc only; no frontend code changed.

## Solution
_Backfilled on 2026-11-14 from the code and its comments, after the ticket closed. The original owner should correct anything that differs from their actual reasoning._

**Chosen:** A single reference document, `doc/style.md`, covering colour tokens, Doto type rules, dot sizes, board and map components, and mobile and touch rules. It links the artifact mocks (the board + 3D map mock is the approved reference) and ends with a numbered **Open decisions** list instead of deciding anything outside scope. Frontend tickets 4.1-4.6 link to it, and the restyle itself is ticket 4.8.

**Strengths**
- One place for every visual rule, so parallel frontend tickets stay consistent.
- Keeps scope and stack unchanged. Scope questions (3D map, Plotly vs dot charts, where the panorama goes) are raised for the team instead of settled in a style doc.
- Writing it as a doc first means no code churn while those decisions are open.

**Limitations**
- The approved mock depends on a 3D map that is currently out of scope. Parts of the doc can't be built until the team decides.
- The mocks exist only as claude.ai artifacts, not in the repo (open decision 5).
- The 2 px map cell size hasn't been checked for frame rate on phones (open decision 6).

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Go straight to CSS tokens in code | Decisions on Plotly and 3D were still open | Faster visible result, but likely rework |
| Storybook or a component library | Not in the stack; too heavy for five panels | Living examples, but more tooling |
| Follow the approved mock fully, 3D included | Would change scope without team agreement | Matches the mock, but breaks the scope rules |
