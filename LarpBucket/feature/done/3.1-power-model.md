# 3.1 Sun disc fraction and power

Status: done
Owner: Tam Nguyen
Source: scope.md > Model (disc fraction, power), Core 4 Metrics (Power)

## Description
In `backend/app/model.py`, add `disc_fraction(sun_el, skyline_el)` using `f = 1 - (acos(x) - x*sqrt(1-x^2))/pi`, `x = (sun_el - skyline_el)/0.267°`, clamping x to [-1, 1]. Add `power(sun_el, f, area, efficiency) = 1361 * area * efficiency * cos(sun_el) * f`. Derive Wh/day and % time sunlit.

## Expected user interaction
Caller passes Sun elevation, skyline elevation at the Sun's azimuth, and panel params; gets power in W per time step.

## Done when
- `disc_fraction` returns 0 / 0.5 / 1 at x = -1 / 0 / 1 and never NaN
- Unit tests in `backend/tests/test_model.py`

Note: done. Added the power model and unit coverage for disc fraction, wattage, and power summaries.


## Solution
_Backfilled on 2026-11-14 from the code and its comments, after the ticket closed. The original owner should correct anything that differs from their actual reasoning._

**Chosen:** `disc_fraction`, `power` and `summarize_power` live in `backend/app/utils.py` (moved from `model.py` by the 3.1 code-structure refactor). The `PowerMetrics` result type is in `backend/app/model.py` and the constants (1361 W/m², 0.267° Sun radius) are in `backend/app/constants.py`. The functions are vectorised with NumPy, take angles in radians, clamp `x` to [-1, 1] and the result to [0, 1], and return a float for scalar input or an array otherwise.

**Strengths**
- Follows the scope.md formulas exactly. Clamping removes NaNs from `acos` and `sqrt` at the edges.
- Works on whole time series at once, which suits the per-step arrays from ephemeris and horizon.
- Pure functions with no SPICE or DEM dependency, so they are quick to unit test.

**Limitations**
- Angles are in radians. `ephemeris.sun_earth_azel` now returns radians too, so its output can be passed in directly; only degree inputs from elsewhere (e.g. the API) need converting.
- `cos(sun_el)` assumes a vertical panel always facing the Sun's azimuth. Panel orientation is ticket 6.2.
- No eclipse or Earth occultation (6.1), and efficiency is a single constant (6.3).
- The disc-fraction formula is the area of a circle cut by a straight horizon line. It ignores skyline slope across the Sun's 0.53° disc (6.5).

**Alternatives considered**
| Option | Why not chosen | Trade-off vs chosen |
|---|---|---|
| Point-source Sun (sunlit if `sun_el > skyline_el`) | Scope asks for a disc fraction; polar sites graze the horizon often | Simpler, but power jumps between 0 and full |
| Linear ramp across the disc | Not the formula in scope.md | Cheaper, with up to about 9% error mid-disc |
| Degrees at the API boundary | Not done; open trade-off | Matches `ephemeris.py` and removes the unit trap, at the cost of converting inside each function |
