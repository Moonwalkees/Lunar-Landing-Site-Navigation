# 4.29 Remember the user's setup between visits

Status: in-progress
Owner: Maddie
Source: doc/scope.md > Core 1 (custom sites), Core 3 (rover numbers); doc/tech-stack.md > Frontend (client state); user request 2026-11-15

## Description
Everything the user sets up is lost on reload, and on the CLASSIC VIEW / BOARD VIEW switch, which reloads the page (4.22). Keep it in the browser's `localStorage` so it comes back: on the board, the custom sites, the presets the user deleted, the mission window (start, days, step) with its rover numbers, the selected site and the sort order; on classic, the site form (site, window and rover). No backend or accounts: this is per browser only.

## Expected user interaction
The user adds a custom site, deletes a preset and runs a different window with their own rover numbers. They reload, or flip to the classic UI and back, and find the same board. A RESET button next to RUN clears what was saved and returns to the defaults.

## Done when
- Board: custom sites, deleted presets, the window and rover the user ran, the selected site and the sort order survive a reload
- Classic: the site form (site, window, rover) survives a reload
- A window the user never ran is not saved, so the default start date stays "today" on every visit
- Saved data is checked on load; bad or old data is ignored, never crashes the app
- Works when browser storage is blocked (the app behaves as before)
- RESET clears the saved setup and restores the defaults
- `npm run build` passes
