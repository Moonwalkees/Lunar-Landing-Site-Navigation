# 7.6 Per-cell horizon, power and comms fields

Status: open
Owner:
Source: Extension feature (user request: near-future power/comms change heatmap). Builds on doc/2d-view.md and the scope.md > Core 4 model (Sun disc fraction, Earth margin thresholds).
Depends on: BUG-010 (fast shadow pass)

## Description
The forecast heatmap (7.7 to 7.9) needs a power value and a comms value for every cell of the `GET /terrain` grid at any time step. Today only `sunlight()` in `frontend/src/terrain2d.ts` exists, and it gives the Sun only. Split its terrain march into a reusable horizon pass and build both fields on it:

- `horizonToward(grid, az, el): Float32Array`: the local horizon elevation in degrees per cell, looking along `az`, with curvature included. It uses the fast sweep from BUG-010.
- `sunlight()` becomes a wrapper over `horizonToward` and returns the same output as today.
- `earthLink(grid, az, el): Float32Array`: `clamp(margin / 0.5°, 0, 1)`, where `margin = el − horizon`. On this scale 0 is blocked, 0 to 1 is marginal and 1 is clear, matching the scope.md thresholds.
- `powerField(grid, sun, behindEarth)` returns the Sun disc fraction × (1 − behindEarth). `commsField(grid, earth)` returns `earthLink`.

Both fields run from 0 to 1, so the heatmap can use one colour scale for both. The Sun and Earth az/el come from the `/analyze` response and apply to the whole 24 km grid.

## Expected user interaction
None visible. The 2D map looks exactly as before. Callers pass a grid and a Sun or Earth az/el and get back an n×n `Float32Array`.

## Done when
- `sunlight()` output matches the old version (max abs diff < 0.01) on the Shackleton grid
- At the centre cell, `earthLink` agrees with `/analyze` `comms[t]` for most steps. Differences are expected only where terrain beyond 12 km is the blocker
- `npm run build` passes
